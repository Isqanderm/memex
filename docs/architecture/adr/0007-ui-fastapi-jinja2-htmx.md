# ADR-0007: UI — FastAPI + Jinja2 + HTMX

**Статус:** accepted
**Дата:** 2026-05-29
**Автор:** Александр Мельник

---

## Контекст

Memex нужен веб-интерфейс для загрузки документов и поиска. Система личная (один пользователь), поэтому богатый SPA-интерфейс не оправдан. Приоритет — минимум усложнений, быстро работающий инструмент.

## Рассматриваемые варианты

### Вариант 1: FastAPI + Jinja2 + HTMX

Серверный рендеринг HTML. FastAPI отдаёт страницы через Jinja2 шаблоны. HTMX позволяет делать частичные обновления страницы (без полного reload) через атрибуты в HTML.

**Как работает:** браузер запрашивает страницу → FastAPI рендерит HTML → HTMX делает AJAX-запросы и подставляет HTML-фрагменты в DOM.
**Плюсы:**
- Один процесс — нет отдельного фронтенд-сервера
- Нет JavaScript фреймворка, нет сборки
- Достаточно интерактивности для личного инструмента (поиск без reload, загрузка файлов)
- Легко добавить новую страницу — просто новый шаблон
**Минусы:**
- Ограниченный UX по сравнению с SPA (нет real-time, сложная анимация)
- Jinja2 шаблоны менее удобны для сложных компонентов
**Риски:**
- Если потребуется богатый интерфейс — придётся мигрировать на SPA

### Вариант 2: FastAPI API + React/Vue SPA

FastAPI только JSON API, отдельный фронтенд-проект.

**Как работает:** два приложения — бэкенд и фронтенд, собираются и деплоятся отдельно.
**Плюсы:**
- Полноценный UX, rich interactions
- Разделение ответственности
**Минусы:**
- Два проекта, две точки деплоя
- Нужен Node.js, npm, сборка
- Избыточно для личного инструмента
**Риски:**
- Сложность фронтенд-стека несоразмерна задаче

### Вариант 3: Только API + MCP, без UI

Интерфейс — только через Claude Code MCP и прямые API вызовы.

**Плюсы:**
- Нет фронтенд-кода вообще
**Минусы:**
- Неудобно просматривать проиндексированные документы
- Загрузка файлов через curl — неудобно

## Решение

Выбрал **Вариант 1: FastAPI + Jinja2 + HTMX**.

Личный инструмент, интерфейс простой: форма поиска, список документов, страница загрузки. HTMX даёт достаточно интерактивности (поиск без reload, прогресс загрузки) без JavaScript фреймворка и сборки. Один процесс — проще деплой и разработка.

**Страницы MVP:**
- `GET /` — форма поиска + результаты (HTMX)
- `GET /documents` — список проиндексированных документов
- `POST /upload` — загрузка файла (multipart, HTMX progress)

## Последствия

**Придётся:**
- Добавить `src/ui/` модуль с Jinja2 шаблонами и роутами
- Добавить зависимости: `jinja2`, `python-multipart`
- Разделить роуты: `src/api/` — JSON API, `src/ui/` — HTML роуты
- Статика (CSS, HTMX JS) — через `StaticFiles` в FastAPI

**Стало проще:**
- Один процесс, один деплой
- Нет сборки, нет Node.js

**Путь к миграции:** JSON API (`src/api/`) уже есть и не зависит от UI. Если потребуется SPA — фронтенд пишется поверх того же API без изменений бэкенда.

**Разделение роутов:**
```
src/api/   → /api/documents, /api/query   (JSON, для MCP и прямых вызовов)
src/ui/    → /, /documents, /upload       (HTML, для браузера)
```
Оба используют одни и те же сервисы из `ingestion/` и `retrieval/`.
