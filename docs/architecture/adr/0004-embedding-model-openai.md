# ADR-0004: Embedding Model — OpenAI text-embedding-3-small

**Статус:** superseded by ADR-0016
**Дата:** 2026-05-29
**Автор:** Александр Мельник

> **Устарел** (2026-06-02): в v2.0.0 заменён на локальную модель `intfloat/multilingual-e5-small` (384 dims).
> Причина: устранение зависимости от API, снижение latency с ~1400ms до ~50ms, нулевая стоимость.
> Новое решение: ADR-0016.

---

## Контекст

Semantic search требует преобразования текста в векторы. Нужно выбрать embedding модель. Корпус многоязычный (RU + EN минимум). Качество embedding напрямую влияет на recall semantic search.

## Рассматриваемые варианты

### Вариант 1: OpenAI text-embedding-3-small

API модель от OpenAI, 1536-мерные векторы.

**Как работает:** HTTP запрос к OpenAI API при индексации и при каждом поисковом запросе.
**Плюсы:**
- Лучшее качество из доступных моделей такого размера
- Нативная мультиязычность (RU, EN и другие выровнены в одном пространстве)
- Zero setup: только API ключ
- Стоимость минимальна: ~$0.02 / 1M токенов (~$0.001 на документ)
**Минусы:**
- Зависимость от внешнего API (недоступность сети = нет индексации)
- Latency сети ~100-200ms на батч чанков при индексации
**Риски:**
- Изменение API или цен (маловероятно на горизонте проекта)

### Вариант 2: Локальный sentence-transformers

`all-MiniLM-L6-v2` или `nomic-embed-text`, запуск на CPU/GPU локально.

**Как работает:** модель загружается в память, inference локально.
**Плюсы:**
- Бесплатно, работает офлайн
- Нет latency сети при индексации
**Минусы:**
- Заметно хуже качество на RU (5-15% по бенчмаркам)
- Скачать и хранить ~500MB модели
- На CPU: ~50ms/чанк — быстро, но хуже recall
**Риски:**
- Русскоязычный корпус — recall существенно хуже чем у OpenAI модели

## Решение

Выбрал **Вариант 1: OpenAI text-embedding-3-small**.

Recall — приоритет. На смешанном RU+EN корпусе качество локальных моделей заметно хуже. Стоимость при корпусе < 1000 документов ничтожна (< $1 на полную переиндексацию). Latency при индексации не критична — индексация происходит редко. При каждом поисковом запросе нужен один embed вызов (~150ms) — приемлемо для интерактивного использования.

## Последствия

**Придётся:**
- Хранить `OPENAI_API_KEY` в env
- Реализовать батчинг при индексации (OpenAI принимает до 2048 текстов за раз)
- Graceful degradation при недоступности API (вернуть ошибку, не падать)

**Стало проще:**
- Нет управления моделями, весами, зависимостями ML-фреймворков
- Кросс-языковой поиск работает без дополнительной конфигурации

**Путь к миграции:** если в будущем нужна полная офлайн-работа — заменить `EmbeddingStage` на локальную модель. Остальной pipeline не меняется.
