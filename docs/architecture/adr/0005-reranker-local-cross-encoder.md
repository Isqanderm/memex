# ADR-0005: Reranker — Локальный Cross-encoder

**Статус:** accepted
**Дата:** 2026-05-29
**Автор:** Александр Мельник

---

## Контекст

После RRF слияния у нас 5-10 L2 чанков (~512 токенов каждый). RRF ранжирует по позиции в списках поиска, но не читает содержимое чанка вместе с запросом. Нужен финальный шаг, который оценивает релевантность пары (query, chunk) как единое целое.

Проблема без reranker: BM25 может дать высокий ранг чанку где нужное слово есть, но контекстуально не отвечает на вопрос. Semantic может ошибиться на коротких запросах.

## Рассматриваемые варианты

### Вариант 1: Без reranker

Передать top-5 L2 чанков по RRF score напрямую в LLM.

**Как работает:** нет дополнительного шага.
**Плюсы:**
- Нет latency reranker
- Нет дополнительной зависимости
**Минусы:**
- Ложные срабатывания BM25 попадают в контекст LLM
- LLM получает нерелевантные чанки и может галлюцинировать
**Риски:**
- Качество ответов зависит от шума в контексте

### Вариант 2: Локальный cross-encoder

`cross-encoder/ms-marco-MiniLM-L-6-v2` (~80MB), запуск на CPU.

**Как работает:** модель получает `(query + [SEP] + chunk)` и выдаёт score 0..1. Оба текста обрабатываются вместе — модель видит их взаимодействие.
**Плюсы:**
- Существенно точнее bi-encoder: видит query и chunk одновременно
- Бесплатно, работает офлайн
- Малый размер (~80MB), работает на CPU за 100-150ms на 5-10 чанков
- Убирает ложные срабатывания BM25
**Минусы:**
- Дополнительная ML-зависимость (sentence-transformers)
- ~100-150ms latency на CPU — добавляется к общему времени ответа
**Риски:**
- Модель обучена на EN данных, качество на RU чанках чуть хуже (приемлемо)

### Вариант 3: Cohere Rerank API

Внешний API для reranking.

**Как работает:** HTTP запрос с query и чанками, получаем ранжированный список.
**Плюсы:**
- Лучшее качество из коробки
- Мультиязычная модель
**Минусы:**
- Внешняя зависимость (как OpenAI, но ещё один сервис)
- Стоимость на каждый запрос
- Latency сети
**Риски:**
- Два внешних API в критическом пути запроса — нежелательно

## Решение

Выбрал **Вариант 2: Локальный cross-encoder**.

Reranker критически важен для quality: убирает ложные срабатывания BM25 и улучшает финальный порядок перед LLM. Локальная модель достаточно хороша для задачи (MSMARCO — сильная baseline), работает за 100-150ms, не требует API ключей. Добавлять второй внешний API (Cohere) нежелательно — увеличивает хрупкость системы. Latency 150ms приемлема для личного инструмента.

Reranker запускается **после** Expand to L2 — видит полные 512-токенные чанки, а не маленькие L1 фрагменты. Это важно: больше контекста = точнее оценка релевантности.

## Последствия

**Придётся:**
- Добавить `sentence-transformers` в зависимости
- Реализовать `Reranker` класс с кешированием загруженной модели (один раз при старте)
- Возвращать top-3-5 чанков после reranking

**Стало проще:**
- LLM получает только действительно релевантные чанки
- Меньше шанс галлюцинаций от нерелевантного контекста

**Путь к улучшению:** если качество на RU недостаточно — заменить на Cohere Rerank API. Интерфейс `Reranker` абстрагирует backend.
